 MeshProtect  v1.2.0
 VRChat アバターのメッシュ保護
════════════════════════════════════════════════════════

  日本語（このファイル） ／ English: README.md ／ 简体中文: QUICK_START_CN.md ／ 한국어: 읽어주세요.txt


  コンポーネントを 1 つ追加して、いつも通り Build & Publish するだけです。

  アップロードされたアバターは、崩したメッシュと、それを元に戻すシェーダーを持ちます。
  持ち主が Expression メニューから 6 桁のパスワードを入れたときだけ元に戻り、抜き出
  した人の手元には、開くことも編集することも売り直すこともできない、無関係な点の集ま
  りだけが残ります。

  アルゴリズムはアバターごとに違います。あるアバター用に書かれた解除スクリプトは、次
  のアバターでは何もしません。
  無料配布です。BOOTH: https://humuhumuhumu.booth.pm/items/8731588


■ 対応シェーダー

  lilToon 2.x  ネイティブ対応。テッセレーションも v1.2.0 から保護できます。lilToon
               公式の拡張点を通しており、フォークもパッチも当てていないため、lilToon
               の更新で壊れません
  その他 6 種  Poiyomi Toon ／ Xiexe's Toon Shader ／ UnityChanToonShader ／
               Sunao Shader ／ GTAvaToon ／ blackbody。生成した解錠処理をパスごとに、
               テキスト置換ではなくセマンティクスで自動移植します
  lilSSAO ／   どちらも lilToon のカスタムシェーダーファミリーなので、移植ではなく
  lilSSRT      フォルダーごとアバター用の生成先へ複製し、そこへ解錠処理を統合します。
               ホスト側のプロパティも専用インスペクターもそのまま使えます。テッセ
               レーション版だけは対象外で、無保護のまま（壊れずに）出力されます

  lilToon 2.0.0 でメッシュ暗号化機能が廃止されました。本ツールがその穴を埋めます。

  v1.1.0 以前から更新した場合は、Mesh Protect Root の「詳細設定」にある「シェーダー
  を再生成」を一度押してください。テッセレーションの新しい解錠処理はそこで組み込ま
  れます。押すまでは、テッセレーションを使うマテリアルだけが（壊れる代わりに）無保
  護のまま出力され、アップロードレポートに警告が出ます。

  旧版「lilToonMeshProtect」を入れたままのプロジェクトでは、まず Mesh Protect Root
  で 6 桁のパスワードを控えてから、旧版のフォルダーを削除して Unity を再起動して
  ください。フォルダー名が違うためインポートしても旧版は自動では消えず、両方が
  残るとアセットの GUID が衝突します。


■ 導入

  BOOTH で .unitypackage を入手してインポートするか、本リポジトリを UPM / VPM
  パッケージとして追加してください： https://github.com/edonamea/MeshProtect.git
  Unity 2022.3 ／ VRChat Avatar SDK3 ／ lilToon 2.x ／ PC 向けアバター
  UI は 日本語 / English / 简体中文 / 한국어 に対応しています。


■ 使い方

  1. アバターのルートを選択 → Add Component → MeshProtect / Mesh Protect Root
  2. 「パスワードを生成」を押す。6 桁・各桁 1〜8。必ず控えてください ―― VRChat のパ
     スワード保存は PC ごとなので、別の PC では入れ直しになります
  3. いつも通り Build & Publish
  4. VRChat で Expressions → Unlock → 各桁を選ぶ

  ※ SDK がこのコンポーネントについて赤いエラーを出しますが、Auto Fix は押さないでく
    ださい。「クライアントで削除されます」は事実で、無害です ―― SDK が作る一時コピー
    からビルド時に取り除かれるためです。Auto Fix はシーン上のコンポーネントを削除し、
    パスワードも一緒に失われます。赤いまま Build & Publish を押してください。

  ベイクボタンも、シーンに置く 2 体目のアバターも、モデル編集後にやり直す作業もあり
  ません。保護がかかるのは SDK が作る一時コピーだけで、あなたのプロジェクトは 1 バイ
  トも変更されません。コンポーネントを外せば、次のアップロードは普通のアバターです。

  衣装・PhysBone・Modular Avatar・VRCFury・メッシュ最適化ツールとは、順序を問わずそ
  のまま併用できます。Quest（Android）ビルドは素通りするので、PC と Quest でチェック
  を切り替える必要もありません。

  パスワードだけの変更は即座に完了し、アルゴリズムはそのまま残ります。「保護を作り直
  す」（New Protection）はアルゴリズムごと引き直します。自分の複数のアバターで同じパ
  スワードを使っても、アルゴリズムが違うため変位のしかたはまったく別のものになります。


■ 止められること

  ・抜き出したメッシュを Blender で開く → 防げます。先にシェーダーの解析が必要です
  ・バラして貼り替えて別モデルとして売り直す → 防げます。同上
  ・既存の解除スクリプトをかける → 防げます。アルゴリズムはアバターごとに違います
  ・DCC ツールでメッシュを再エクスポートする → 防げます。識別子は UV0 の生ビット列
  ・FX コントローラーから中身を読む → 防げます。レイヤーもステートも改名済み
  ・ロコモーション・ジェスチャー・エモートを読む → 防げます。上がるのは改名済みコピー
  ・メッシュ名・マテリアル名を読む → 防げます。アバター自身のアルゴリズムから生成
  ・オブジェクト名・パラメータ名を読む → 改名されます（クライアント駆動分を除く）
  ・このアバターのシェーダーを手で解析する → 数時間かかり、次のアバターには効きません

  目指しているのは「絶対に破られない」ことではなく、破る手間が 1 体ごとに丸ごと掛か
  り直すことです。モデルが出回るときに実際に起きることの大半は、自動化された大量のリッ
  ピングです。それが成立しなくなります。


■ ビルドのたびに検証されます

  この種のツールは黙って失敗し、気づくのはゲームの中です。本ツールはアップロード前に、
  自分の仕事を自分で検証します。生成シェーダーを C# 側の暗号と GPU 上で突き合わせ、
  焼いたメッシュを頂点ごと、ブレンドシェイプの全フレームで復号して比べ、解錠メニュー
  と伝送用パラメータが揃っていることを確かめ、全コンポーネントのシリアライズ済みフィー
  ルドを歩いて、保護前のメッシュがどこからも参照されていないことを確認します。対応し
  きれない部分には手を付けず、Console に名前を出すため、ビルドが壊れたアバターを作る
  ことはありません。


■ 仕組み

  ・変位は「保存」ではなく「生成」されます。各頂点を、パスワードと頂点自身の識別子か
    ら作ったハッシュの値だけ接線・法線方向に押し出すので、メッシュの中に逆算できる係
    数は残りません。
  ・アルゴリズムはアバターごとに違います。パスワードを設定するたびに新しいハッシュプ
    ログラムが組み立てられ、その定数を焼き込んだシェーダーファミリーが丸ごと生成され
    ます。プロパティ名もパラメータ名もアセット名も生成されるため、アップロードされた
    アバターの中にこのツールの名前は 1 つも残りません。
  ・ロック中のアバターは、崩れるのではなく消えます。全頂点が 1 点に潰れるので、どの
    パスにも何も描かれません。パスワードが違うときも同じなので、アバターは「正しい」
    か「見えない」かのどちらかで、他人の前で崩れた姿を晒すことはありません。
  ・演算はすべて整数なので、C# と HLSL はどの GPU でもビット単位で一致します。ブレン
    ドシェイプも補正されます。


■ 動作コスト

  頂点あたり float 1 つ（TEXCOORD6）／ Expression パラメータ 24 bit ／ 頂点シェーダー
  に数命令でパフォーマンスランクは変わらず ／ シェーダー生成にパスワード 1 つあたり
  約 3.5 秒、再アップロードは追加コスト 0。
