  컴포넌트를 하나 붙이고, 평소처럼 Build & Publish 하면 끝입니다.

  업로드되는 아바타는 흐트러진 메시와, 소유자가 Expression 메뉴에서 6자리
  비밀번호를 넣었을 때만 되돌리는 셰이더를 함께 가집니다. 파일을 뜯어 간 사람
  손에 남는 것은, 열 수도 편집할 수도 되팔 수도 없는 무관한 점의 집합입니다.

  알고리즘은 아바타마다 새로 만들어지므로, 한 아바타를 상대로 쓴 스크립트는
  다음 아바타에 통하지 않습니다. 무료이고, BOOTH 에서 배포하고 있습니다.
  https://humuhumuhumu.booth.pm/items/8731588


■ 지원 셰이더

  lilToon 2.x … 네이티브. lilToon 공식 커스텀 셰이더 확장 지점을 통하므로,
  포크하거나 패치하는 곳이 없고 lilToon 이 업데이트되어도 깨지지 않습니다.

  Poiyomi Toon · Xiexe's Toon Shader · UnityChanToonShader · Sunao Shader ·
  GTAvaToon · blackbody … 자동 이식. 생성된 해제 처리를 그 셰이더에 패스
  단위로 복사해 넣습니다. 위치는 텍스트 패치가 아니라 시맨틱으로 찾습니다.

  lilSSAO · lilSSRT … 둘 다 lilToon 커스텀 셰이더 패밀리이므로, 이식이 아니라
  폴더째 아바타용 생성 위치로 복제한 뒤 그곳에 해제 처리를 통합합니다. 호스트
  쪽 프로퍼티도 전용 인스펙터도 그대로 쓸 수 있습니다. 테셀레이션 판만은
  대상에서 제외되어, 보호되지 않은 상태로(깨지지 않고) 출력됩니다.

  lilToon 2.0.0 에서 자체 메시 암호화 기능이 없어졌습니다. 그 자리를 메웁니다.

■ 사용 방법

  1. 아바타 루트 → Add Component → MeshProtect / Mesh Protect Root
  2. 「비밀번호 생성」을 누릅니다. 6자리, 각 자리 1~8. 반드시 적어 두세요.
     VRChat 은 PC 단위로 저장하므로, 다른 PC 에서는 다시 입력합니다.
  3. 평소처럼 Build & Publish
  4. VRChat 에서 Expressions → Unlock → 자리마다 숫자 선택

  ※ SDK 가 이 컴포넌트에 대해 빨간 오류를 냅니다. Auto Fix 는 절대 누르지
    마세요. 「클라이언트에서 제거됩니다」는 사실이고 무해합니다——빌드 훅이
    SDK 가 빌드에 쓰는 복사본에서 빼기 때문입니다. Auto Fix 는 그 대신 씬의
    컴포넌트를 삭제하고, 비밀번호도 함께 사라집니다.

  베이크 버튼도, 씬의 두 번째 아바타도, 모델을 편집한 뒤에 다시 할 것도
  없습니다. 보호가 걸리는 것은 SDK 가 빌드에 쓰는 임시 복사본뿐이라 당신의
  프로젝트는 변경되지 않고, 컴포넌트를 제거하면 다음 업로드는 평범해집니다.

  의상·PhysBone·Modular Avatar·VRCFury·메시 최적화 도구와 순서에 상관없이
  함께 쓸 수 있고, 보호는 그것들 전부의 뒤에 실행됩니다. Quest 업로드는
  그대로 통과하므로 두 빌드 사이에서 켜고 끌 것도 없습니다.

  비밀번호만 바꾸면 즉시 끝나고 알고리즘은 그대로이며, 「보호 재생성」은
  알고리즘째로 다시 만듭니다. 여러 아바타에 같은 비밀번호를 써도 됩니다.
  알고리즘이 아바타마다 다르므로, 같은 6자리라도 변위 방식은 완전히 다릅니다.


■ 무엇을 막을 수 있는가

  파일을 뜯어 Blender 로 연다 … 막힙니다. 먼저 셰이더를 되돌려야 합니다
  분해해서 텍스처만 갈아 끼워 되판다 … 막힙니다. 같은 이유입니다
  기존의 해제 스크립트를 돌린다 … 막힙니다. 같은 알고리즘이 둘도 없습니다
  DCC 도구로 다시 내보낸다 … 막힙니다. 정점의 신원이 UV0 의 비트 패턴입니다
  FX 컨트롤러로 무엇을 하는지 읽는다 … 막힙니다. 레이어와 클립이 개명됩니다
  로코모션·제스처·이모트를 읽는다 … 막힙니다. 보호된 복사본이 올라갑니다
  메시와 머티리얼의 이름을 읽는다 … 막힙니다. 이름도 알고리즘이 생성합니다
  오브젝트·파라미터 이름을 읽는다 … 개명되고, 클라이언트가 쓰는 것만 남습니다
  컴파일된 셰이더를 직접 되돌린다 … 몇 시간이 들고, 다음 아바타엔 무의미합니다

  목표는 「절대 못 뚫는다」가 아니라 「뚫어도 규모가 되지 않는다」입니다.
  비용은 모델 1개마다 처음부터 다시 들고, 모델이 돌아다닐 때 실제로 일어나는
  일의 대부분인 오프라인 대량 스크립트가 성립하지 않게 됩니다.


■ 빌드마다 스스로 검증합니다

  이 분야의 도구는 조용히 실패하고, 알아차리는 것은 게임 안입니다. 이 도구는
  업로드가 끝나기 전에 자기 일을 스스로 증명합니다. 생성된 셰이더를 GPU 위에서
  C# 쪽 암호와 대조하고, 구운 메시를 전부 되돌려 블렌드 셰이프 프레임까지 정점
  단위로 비교하고, 잠금 해제 메뉴와 전송용 비트가 빠짐없이 있는지 확인하고,
  모든 컴포넌트의 직렬화된 필드를 훑어 원본 메시에 닿는 경로가 남지 않았음을
  증명합니다. 다룰 수 없는 것은 손대지 않은 채로 두고 Console 에 이름을
  적으므로, 빌드가 망가진 아바타를 만들어 내는 일은 없습니다.


■ 작동 원리

  ・변위는 저장하는 것이 아니라 생성합니다. 각 정점은 비밀번호와 그 정점
    자신의 신원을 해시한 값만큼 탄젠트와 노멀 방향으로 밀려나므로, 메시
    안에는 되읽을 계수가 존재하지 않습니다.
  ・알고리즘은 아바타마다 새로 만들어집니다. 비밀번호를 설정하면 해시
    프로그램이 새로 조립되고, 그 상수를 코드에 박아 넣은 셰이더 패밀리가
    통째로 출력됩니다. 프로퍼티·파라미터·에셋 이름도 함께 생성되므로,
    업로드된 아바타 안에 이 도구를 가리키는 것은 아무것도 없습니다.
  ・잠긴 아바타는 흐트러진 모습이 아니라 아예 보이지 않습니다. 모든 정점이
    한 점으로 모여 어느 패스도 래스터화되지 않고, 틀린 비밀번호도 마찬가지라
    남들 앞에서 흐트러진 모습을 보이는 일은 없습니다.
  ・연산은 전부 정수라서 C# 과 HLSL 이 어느 GPU 에서도 비트 단위로
    일치합니다. 블렌드 셰이프도 보정합니다.


■ 오버헤드

  정점마다 float 하나 (TEXCOORD6) · Expression 파라미터 예산 24 bit · 버텍스
  셰이더 명령어 몇 개로 아바타의 퍼포먼스 랭크는 바뀌지 않음 · 비밀번호 1개당
  한 번, 셰이더 패밀리 컴파일에 약 3.5초, 재업로드에는 추가 비용 없음.
